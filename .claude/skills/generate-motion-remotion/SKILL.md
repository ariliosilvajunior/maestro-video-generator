# Skill: generate-motion-remotion (Phase 5 — Motion Graphics + Merge)

> **DEFAULT = 6-SECTION GRAMMAR, NO STOCK B-ROLL (house rule).** The current default
> is the section-driven grammar (see "MANDATORY STRUCTURE" below): visual variety comes from distinct
> MOTION IDEAS, real screenshots, and the full-frame/split/avatar canvases — NOT from stock b-roll.
> **Phase 4 stock-b-roll selection and Phase 7 insert-b-roll are SKIPPED for grammar videos** (the
> `_motion.mp4` render IS the deliverable; subtitles burn directly onto it). Capture REAL reference
> screenshots in Phase 4 instead (capture-references). Reference builds: `src/compositions/PremiumSectionRef.tsx` (premium) / `HandDrawnGrammarRef.tsx` (hand-drawn).
>
> **(LEGACY b-roll-window path, pre-grammar):** if ever building the old stock-b-roll style, `select-brolls-stock` resolved each window to HIT (clip in `<Name>_broll_manifest.json`) or MISS, and you built a MOTION scene over every MISS window leaving HIT windows empty. Not used by the section grammar.

## MANDATORY STRUCTURE — SECTION REPEATING GRAMMAR (pointer — full spec is canonical elsewhere)

> **CANONICAL SPEC = `motion-pipeline/SECTION_PIPELINE.md`** (section definitions, §1 opening-hook props,
> screenshot motion protocol scroll/zoom/static, motion-idea registry, assertSectionGrammar) **+
> `PIPELINE_DIRECTIVES.md` §2b** (the canonical grammar version + §1 clickbait formulas). **READ BOTH before
> building — do not build the grammar from this skill alone.** Summary: order = **§1 OpeningHook (once)
> → body cycle §3 → §3b → §4 → §5 → §5b → §6, repeating**; pacing ≤2.5s/section; windows snap to SRT
> sentences. Reference comp: `src/compositions/PremiumSectionRef.tsx` (copy it — the grammar is inherited).

Operational rules that live HERE (not in the spec):

- **GAP-FREE SCHEDULING (HARD):** schedule every section with `sectionWindows(fps, [t0,t1,…])` from `../library` — NEVER `durationInFrames={F(t2-t1)}` (1-frame gaps flash the avatar frame). **NO continuous avatar-frame behind everything (QCR-109):** one root `<Audio>`, `<PremiumBg frame={false}/>` floor, each SPLIT wraps its OWN `<PremiumFrame muted trimBefore>`; author sections in TIME order. Evidence sections: NO caption text below the screenshot.
- **§3b/§5b SUPPRESS the burned subtitle in their windows** — list both types' `[start,end]` in `<Name>_caption_windows.json` and run `subtitle-pipeline/suppress_windows.py` before the Phase-8 burn.
> **CAPTION-SYNC CONTRACT (QCR-229, mandatory — the rule that stops a shipped caption desync from recurring):** because the burned subtitle is DELETED inside every §3b/§5b window, that caption is the ONLY text on screen there, so it MUST match the audio spoken in its OWN window. Two hard rules: (1) **VERBATIM** — set each §3b/§5b caption to the actual SRT words spoken inside that window (copy them straight from the SRT cue; do NOT paraphrase, distill, or reuse the previous section's line — a real run had W[5] showing "Sem mensalidade, sem limite" and W[8] showing "Instala uma vez, gera pra sempre", both the PRIOR section's line, while the audio had already moved on). `groups={[...]}` 2-word distillation is allowed ONLY for the short CTA. (2) **SNAP** — the window `[start,end]` MUST equal the SRT sentence boundaries of the line it captions; never start/end a caption mid-sentence. Then **emit `<downloads>/<Name>_caption_segments.json`** as the single source of truth: `[{ "win":[s,e], "text":"<exact on-screen caption>", "kind":"reveal|avatarcap|groups" }, …]` for every §3b/§5b section (write `<Name>_caption_windows.json` from the same `win`s). Right after registering the composition and BEFORE rendering, run the gate:
> ```bash
> python3 subtitle-pipeline/verify_caption_sync.py --srt <downloads>/<Name>.srt --segments <downloads>/<Name>_caption_segments.json --name <Name>
> ```
> Exit 0 = proceed to render. **Exit 1 = a caption shows text not spoken in its window → fix the caption text/window in the .tsx, re-emit the JSON, rerun the gate until green BEFORE you render** (catching it here is free; catching it at Phase 8 forces a full re-render).
>
> **§4 HERO-LABEL COMPLEMENT GATE (QCR-112, mandatory — run BEFORE rendering, same as the caption-sync gate).** The QCR-112 complement rule ("diff each §4 hero label vs its concurrent subtitle") kept being skipped by hand and shipping a real -5 MOTION_DUPLICATE at QC (a real run: "O VÍDEO PRONTO PRA POSTAR" vs subtitle "vídeo pronto pra postar." = 4 consecutive → grade 95; same family logged repeatedly). It is now a deterministic gate — run it right after the caption-sync gate:
> ```bash
> python3 motion-pipeline/check_hero_label_complement.py --tsx motion-pipeline/remotion-agent/src/compositions/<Name>.tsx --ass <downloads>/<Name>.ass
> # (before the .ass exists at Phase 5, pass --srt <downloads>/<Name>.srt instead)
> ```
> Exit 0 = proceed to render. **Exit 1 = a §4 hero `HeroScene label=` / `PremiumLabel` shares 4+ CONSECUTIVE words with a concurrent burned subtitle → distill that label to a NON-verbatim complement (≤3 consecutive shared, e.g. "O VÍDEO PRONTO PRA POSTAR" → "PRONTO PRA MONETIZAR"), re-run the gate until green, THEN render.** §3b/§5b captions are exempt (they ARE the suppressed-subtitle line, QCR-193) and are not checked by this gate.

### Section definitions + motion-idea registry → `motion-pipeline/SECTION_PIPELINE.md` (canonical)

Per-section props (§1 `PremiumOpeningHook` + PillHeadline, §3 zoom-punch alternation, §3b reveal, §4/§5/§6
canvases), the screenshot MOTION PROTOCOL (scroll DEFAULT / zoom 2nd beat with `--focus` from
`prepare_reference_shot.py` / static exception), the `MOTION_IDEAS` registry (`motionideas.tsx`) and the
`assertSectionGrammar` contract (honest `type:concept` ids; throws on adjacent same-type, missing
`split:`/`full:`, caption↔hero ping-pong QCR-147) are ALL specified there — follow the spec, not memory.

Two HARD rules that live HERE (house rules, enforced at the step-5 gates):

1. **LITERAL IMAGE-SEMANTICS** — every image/icon/object MUST depict the LITERAL thing the narration says AT THAT MOMENT, never an adjacent/figurative stand-in (a coin for "documents", a robot for "coding" = QCR-006/QCR-098 DEFECT). Read the exact spoken line for the window, name the concrete noun/action, pick or generate (`generate-image-assets`) the image that SHOWS it. When reusing a keyed library asset, LOOK at it first — the object must BE the thing being said.
2. **MOVING ELEMENTS, not static/pulse** — each motion beat needs ≥1 element in continuous purposeful TRANSLATION (travel/flow/orbit/cascade/count/sweep). Fade-in-then-hold or breathe/pulse as the primary motion = DEFECT. No bouncy AI-slop springs — purposeful, smooth, but it MUST move.

Reference builds validated at QC 100/100: `PremiumSectionRef.tsx` (premium canonical) · `HandDrawnGrammarRef.tsx` (hand-drawn grammar).

find public/assets -maxdepth 1 -mindepth 1 -type d ! -name '<video-name>' ! -name 'icons' ! -name 'sample' -mtime +7 \

du -sh public   # sanity: keep public well under ~300MB before rendering
npx remotion render src/index.ts <CompositionName> <downloads>/<VideoName>_motion.mp4 --codec h264 --crf 16 --timeout 300000 --concurrency 3
# QCR-249: `--concurrency 2 --timeout 120000` FALSE-FAILED at ~frame 1076 with a
# delayRender() "Loading font Anton … not cleared after 118000ms" — a heavy frame (big keyed PNGs + a
# 9141px-tall screenshot) starved one render tab past the per-frame font-load timeout. Bumping to
# --concurrency 3 --timeout 300000 rendered all 1665 frames cleanly. Use these values as the default.
